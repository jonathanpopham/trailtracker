# The IR Atlas

The living model of TrailTracker's shared intermediate representation — the one
graph every language lowers into. This is the human-readable source of truth; the
code mirror is [`src/ir/ontology.rs`](../src/ir/ontology.rs) (the `&'static str`
labels emitted on the wire) and the machine-readable form is
[`ir-atlas.graph.jsonl`](./ir-atlas.graph.jsonl) (the IR described in its own
graph format, so it can be loaded and visualized like any other TrailTracker
graph).

> **Status:** living document. Every new language front end either *maps cleanly*
> into the kinds below or *extends* them through the protocol in
> [§ Extending the IR](#extending-the-ir) — in the same PR, reviewed against this
> file (CODEOWNERS guards `docs/`). Coverage grows; the core stays small.

## Design principles

1. **One graph, all languages.** Rust functions and Python functions are the same
   `Function` node kind, joined by the same `CALLS` edges. Cross-language
   reasoning works because the vocabulary is shared.
2. **Map honestly; never force-fit.** A Python `class`, a Go `interface`, a
   Haskell type class, and a Rust `trait` are all `Type` nodes — distinguished by
   a `type_kind` property and the `language` tag, *not* relabelled to look like
   one another. We do not pretend a class is a struct.
3. **Extend before you lose.** If a language has a construct with no honest home,
   we **add to the IR** — a property, then an edge, then (last resort) a node
   kind. Dropping information is worse than a small, documented addition.
4. **Comprehensible, not a maze.** Additions are justified, named in plain terms,
   and recorded here with a one-line rationale. The core vocabulary stays tight;
   the long tail lives in properties and clearly-scoped edges.
5. **Lossless underneath.** The graph is a *view*; the lossless CST still holds
   every byte. Anything the graph doesn't model is recoverable from the tree.
6. **Distinct definitions get distinct ids.** `Graph::upsert` merges nodes with
   equal ids silently, so an id collision is *invisible data loss* — two
   same-named symbols in different files collapsing into one node (the Go
   build-tag-twin bug, 2026-06). Every node id must therefore embed enough of
   the definition's location (file, line) to be unique per distinct
   definition. Edge resolvability is recovered by index-and-defer passes, never
   by weakening id uniqueness.

## Foundation (why these primitives)

The core is rooted in lambda-calculus-accessible concepts so cross-language
reasoning has a stable floor, with practical code concepts layered on:

| Primitive | λ-concept | Code concept |
|---|---|---|
| `Function` | abstraction (λ) | function / method |
| `CALLS` | application | call site |
| `Constant` | value / literal binding | const / static / top-level binding |
| `Type` | type | struct / class / enum / trait / interface / … |
| `Module` / `File` / `Package` | scope / environment | namespace / file / crate |

## Node kinds

| Kind | Represents | Key properties |
|---|---|---|
| `Package` | crate / assembly / project | `ecosystem` |
| `Module` | a module / namespace scope | `language` |
| `File` | a source file | `path, bytes, lines, extension, language` |
| `Function` | function, method, or associated fn | `qualified_name, line, span_start, span_end, has_body, language` |
| `Type` | type decl (struct/enum/trait/alias/class/interface/…) | `type_kind, qualified_name, line, span_start, span_end, language` |
| `Constant` | const / static / top-level binding | `binding, line, language` |
| `ExternalDependency` | a dependency not in the project | `external, source` |
| `UnresolvedSymbol` | a referenced name with no found definition | `unresolved, role` |
| `Macro` | macro definition / invocation target | *(reserved; not yet emitted)* |

Which kinds each front end emits varies by language (as of 2026-07-01:
`Function` in 37 front ends, `Type` in 26, `Module` in 23, `Package` in 9
manifest-bearing ecosystems; `File` nodes come from the pipeline, not the
lowerings). The per-language emission matrix is to be generated by a
conformance dump, not maintained by hand — see the docs-convergence goal in
[`prompts/goal-verified-atlas.md`](./architecture.md).

## Edge kinds

Every edge has a **domain → range** (valid endpoint kinds). Edges carry
properties only when they add real information.

| Kind | Domain → Range | Means | Properties |
|---|---|---|---|
| `CONTAINS` | File/Module/Package → Module/File | structural containment | — |
| `DECLARES` | File/Module → Function/Type/Constant | a scope declares a definition | — |
| `HAS_METHOD` | Type → Function | a type owns a method (has a receiver) | — |
| `IMPLEMENTS` | Type → Type | a type implements a trait/interface/protocol | `trait_name` |
| `EXTENDS` | Type → Type | class inheritance (is-a), distinct from conforms-to | — |
| `USES_TYPE` | Function/Type → Type | references a type in signature/body | `type_name` |
| `IMPORTS` | File → ExternalDependency/Module | imports a path (`use`/`import`/`using`) | `external, path` |
| `DEPENDS_ON` | Package → ExternalDependency | declared dependency | — |
| `CALLS` | Function → Function/UnresolvedSymbol | a call site (application) | `callee, resolution, candidate_count, method, resolved`, `candidates?`, `ambiguous?` |
| `READS` | Function → Constant | reads a same-module constant binding | — |

## Property conventions

- **Node IDs are structural and human-readable**, not opaque:
  `fn::crate::pkg::mod::name#<line>`, `type::…::Name`, `file::path`, `ext::crate`.
  Where a qualified path + line can still collide (same-named symbols in
  different files sharing one module scope — e.g. Go build-tag twin files),
  the id embeds the relative file path too: `fn::qual#<rel-path>:<line>`.
  Design principle 6 applies: uniqueness per distinct definition is a hard
  invariant; edges reach these ids through index-and-defer resolution passes.
- **`qualified_name`** — the dotted/`::` path to a definition. The cross-language
  join key.
- **`span_start` / `span_end`** — byte offsets into the source, so exact text for
  any node is sliceable straight from the IR (chunking, blame, context windows).
- **`language`** — every node carries its source language; this is how the same
  kind stays honest across languages (a `Type` with `language: python` is a
  class, not a struct).
- **Call resolution provenance** — every `CALLS` edge records *how* it resolved
  (`receiver`/`local`/`qualified`/`import`/`global`) and whether it is certain;
  ambiguity is preserved as a `candidates` set, never guessed.

## Per-language mapping

How each language's surface constructs map onto the IR. ✅ implemented · 🟡 in
progress · ⬜ planned.

> 57 front ends exist as of 2026-07-01; the tables below cover the flagship
> mappings in detail. Which languages are *externally verified* (and to what
> tier) is tracked in [`eval/corpus-manifest.tsv`](../eval/corpus-manifest.tsv),
> not here — verified: python, go, javascript (Tier A); typescript at 2
> explained diffs.

### Rust ✅

| Construct | IR |
|---|---|
| `fn` / method | `Function` (`HAS_METHOD` from the `impl`'s type for methods) |
| `struct`/`enum`/`union` | `Type` (`type_kind: struct\|enum\|union`) |
| `trait` | `Type` (`type_kind: trait`); `impl X for T` → `T IMPLEMENTS X` |
| `type` alias | `Type` (`type_kind: alias`) |
| `const`/`static` | `Constant` (`binding`) |
| `mod` | `Module` |
| `use path` | `IMPORTS` (+ `ExternalDependency` for external roots) |
| `[dependencies]` | `Package DEPENDS_ON ExternalDependency` |
| call / method call | `CALLS` with resolution provenance |
| type in signature/body | `USES_TYPE` |

### Python ✅ (Tier-A verified vs `ast` on django)

| Construct | IR | Notes |
|---|---|---|
| `def` / method | `Function` | methods → `HAS_METHOD` from enclosing `class`; `is_async` property |
| `class` | `Type` (`type_kind: class`) | |
| `class C(Base)` | `C EXTENDS Base` | deferred resolution (pass C) |
| module (`.py` file) | `Module` + `File` | |
| `import` / `from … import` | `IMPORTS` | |
| call | `CALLS` | reuses the resolution ladder |
| same-module constant read in a function body | `READS` | emitted only when the binding is unambiguous and unshadowed |
| `@decorator` | `decorators` property on the definition | `DECORATES` edge still a candidate — see below |

## Extending the IR

When a language has a construct that does not map cleanly, extend — in this
order of preference, least invasive first:

1. **Add a property** to an existing node/edge kind (e.g. `Function.is_async`).
2. **Add an edge kind** when a real relationship has no home (e.g. inheritance).
3. **Add a node kind** — last resort, only for a first-class entity that is truly
   not a Function/Type/Module/Constant.

Every addition: update `src/ir/ontology.rs`, this Atlas (table + changelog), and
`ir-atlas.graph.jsonl`, in the PR that introduces it. Tag it with the
language(s) that motivated it. If a construct is *almost* an existing kind, prefer
the existing kind + a property + a one-line note over a new kind.

### Candidate extensions (logged as languages arrive)

These are anticipated additions — confirmed and implemented when the relevant
front end lands, not before.

| Proposed | Kind | Motivated by | Rationale |
|---|---|---|---|
| `DECORATES` | edge (Function/Type → Function) | Python, JS/TS, Java (`@annotation`) | Decorators/annotations attach behavior to a definition; modeling the link preserves intent without inventing a node. Today decorators are a `decorators` *property*; the edge is promoted when a consumer needs the link traversable. |
| `Function.is_generator` | property | Python, JS, C# (`yield`) | A flavor of `Function`, like the (now implemented) `is_async`. |
| `GROUPING`: `CLASSIFIED_INTO` + `ROLLS_UP_TO` | super-relation + 2 edges | the Lexicon ([lexicon.md](./lexicon.md)) | Architectural clustering output; kept distinct from syntactic `CONTAINMENT`. Enters via this protocol when Phase 3 starts. |
| `Type.type_kind: interface\|protocol\|typeclass\|record\|object\|module` | property values | Go, Swift, Haskell, Scala, Java, Elixir, … | New *values* of the existing `type_kind`, not new kinds — a Go interface and a Swift protocol stay `Type`. |
| `EXPORTS` | edge (Module/File → symbol) | JS/TS, Elixir, Erlang, Elm | Explicit export lists / public surface where it is first-class (e.g. `__all__`, `export`, `-export([...])`). |
| `Field` / `HAS_FIELD` | node + edge | most languages | Struct/class fields, if/when field-level granularity is needed. Deferred until a consumer needs it (YAGNI). |

## Changelog

- **2026-07-01** — Doc reconciled with the code (it had drifted; the
  per-language conformance dump that prevents recurrence is a standing goal).
  `EXTENDS` moved from candidate to core — it has been emitted since the
  Python front end and is now produced by 10+ languages: **9 node kinds,
  9 edge kinds**. `Function.is_async` marked implemented. Recorded design
  principle 6 (id uniqueness — distinct definitions get distinct ids) and the
  file-path-embedding id scheme it forced, both learned from the Go
  build-tag-twin collision. Dropped the stale per-node "Emitted for: Rust"
  column in favor of measured emission counts. Linked the Lexicon design
  ([lexicon.md](./lexicon.md)) and logged its `GROUPING` edges as candidates.
- **2026-06-26** — Atlas created. Core: 9 node kinds, 8 edge kinds (from
  `src/ir/ontology.rs`). Logged candidate extensions for the Python front end
  (`EXTENDS`, `DECORATES`, `is_async`) and the breadth roadmap.
- **2026-06-26** — VIR substrate landed. Added the **relation lattice** to
  `src/ir/ontology.rs`: read-side super-relations `DEPENDS` (subsumes
  `CALLS`/`USES_TYPE`/`IMPORTS`/`DEPENDS_ON`), `CONTAINMENT` (subsumes
  `CONTAINS`/`DECLARES`/`HAS_METHOD`), and `SPECIALIZES` (subsumes `IMPLEMENTS`
  and the now-reserved `EXTENDS` edge constant), mapped by
  `parent_relation(edge)`. These are never emitted on the wire — concrete edge
  labels are unchanged, so goldens stay byte-identical. Also added the
  **`LanguageFrontEnd`** trait + central `front_ends()` registry
  (`src/lang/frontend.rs`); the Rust lowering now sits behind it and the pipeline
  discovers/dispatches/merges all languages into one graph. New front-end API doc:
  [`docs/vir.md`](./vir.md).
