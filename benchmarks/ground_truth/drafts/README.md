# Draft ground truths — REVIEW REQUIRED before use

Everything in this directory is **inert**. `ontology_bench.py` loads only
`ground_truth/*.json` (top level) and never scans `drafts/` — by design.

## Why drafts can't gate

These files were generated by `benchmarks/gt_bootstrap.py` from **the
extractor's own deterministic clusters**: membership comes from
`trailtracker extract domains`, names from the attested LLM pass
(`trailtracker enrich-domains`), and `pathPrefixes` are a greedy cover of each
cluster's member files. Scoring the extractor against a truth derived from
the extractor is circular — the high self-F1 recorded at generation time
validates the *format and prefix derivation*, not the *truth*. Truth requires
a human judgment that these domains match the project's real architecture.

Each draft carries its provenance: the enrichment attestation (backend, model,
prompt hash, timestamp) or the fallback reason, the generation date, the
pinned cohort SHA, per-domain `fileCount` + `prefixCoverage`, and a
`REVIEW-REQUIRED` marker.

## The 10-minute review protocol (per repo)

1. **Open the draft** next to the project's real architecture reference —
   its README/docs, top-level source layout at the pinned SHA, or your own
   knowledge. Every draft has a `reviewHint` field summarizing the documented
   structure to check against.
2. **Judge the domain list** (2 min): Are these the project's actual business
   areas? Delete domains that are vocabulary artifacts (clusters grouped by
   implementation noun, not responsibility). Merge domains the architecture
   treats as one; split ones it treats as several. Rename `name` fields to
   the terms the project itself uses — names are documentation, only
   `pathPrefixes` are scored.
3. **Judge the prefixes** (5 min): For each domain, do the `pathPrefixes`
   describe where that responsibility *actually lives*? Prefer few, shallow,
   architectural prefixes (like eShop's `src/Ordering.`) over long lists of
   deep ones. Long tails of single-file prefixes are a smell — replace them
   with the correct directory or drop them. It is fine (and normal) for the
   reviewed GT to disagree with the clusters; that disagreement is exactly
   what the semantic axis is for.
4. **Strip the scaffolding** (1 min): Remove `REVIEW-REQUIRED`, `derivation`,
   `reviewHint`, `structuralCluster`, `prefixCoverage`, and `fileCount`;
   update `source` to say who reviewed it, against what reference, and when
   (keep the original attestation line for provenance).
5. **Activate** (1 min): `git mv` the file up into `benchmarks/ground_truth/`
   (drop the `.draft` from the name, e.g. `django_domains.json`) and run:

   ```sh
   COHORT_DIR=... python3 benchmarks/ontology_bench.py --check
   ```

   `load_ground_truths()` picks it up automatically by its `repo` field —
   no code change. A reviewed GT that fails the 0.70 macro-F1 gate is a
   *finding about the extractor*, not a reason to soften the GT.

Review the drafts in **randomized order** (dropout discipline — don't let the
first repo reviewed calibrate the rest).
